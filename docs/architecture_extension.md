# Архитектурные границы текущего контура и развития

Документ фиксирует границы модулей, чтобы текущая система оставалась простой,
а формальный rule-based слой можно было добавить отдельно.

## Текущий воспроизводимый контур

Текущий контур отвечает за одну задачу: по сохраненному срезу OpenAlex построить проверяемые авторские показатели, рейтинг, аналитику и отчет.

Основные слои:

- `openalex_dss` - расчетные функции и повторяемый пайплайн обработки среза;
- `apps/api/app/services/storage_paths.py` - разрешение путей срезов, таблиц и запусков;
- `apps/api/app/services/table_engine.py` - общие операции с табличными представлениями DuckDB;
- `apps/api/app/services/ranking_engine.py` - ранжирование авторов;
- `apps/api/app/services/distribution_engine.py` - описательная статистика и распределения;
- `apps/api/app/services/cache_engine.py` - политика кэша аналитических выборок;
- `apps/api/app/services/metric_registry.py` - единый источник названий, формул и подсказок по показателям;
- `apps/api/app/application/scientometric_workflow.py` - прикладные сценарии рейтинга, аналитики и отчета поверх сервисов;
- `apps/api/app/api/query_contracts.py` - единые структуры query-параметров для scope, фильтров и выбора данных;
- `apps/web/src/features/*` - функциональные блоки интерфейса: сценарий работы, таблица данных, формулы, показатели, отчеты, уведомления.

## Текущая поддержка решений

Текущий завершенный контур СППР поддерживает принятие решения не через
rule engine, а через воспроизводимые индексы, сравнение рангов, quality
warnings, scorecard, candidate-metric findings, conclusion draft и report
bundle. Это позволяет обосновать, какой показатель подходит для выбранной
аналитической задачи внутри конкретного `run_id`/`dump_id`, не подменяя
экспертную оценку автоматическим решением.

## Расширение до формальных правил

Слой `apps/api/app/domain/decision_support.py` не выполняет расчет рейтинга
сам. Он задает предметные сущности дополнительного механизма поддержки решений:

- `CandidateProfile` - оцениваемый исследователь или другая сущность;
- `Evidence` - доказательный признак, на котором основан вывод;
- `RuleProfile` - набор правил принятия решения;
- `DecisionCase` - конкретная задача выбора или ранжирования;
- `DecisionRun` - выполнение правила на зафиксированных данных;
- `DecisionPassport` - проверяемое описание входов и результата.

Такое разделение оставляет текущий наукометрический расчет независимым от
формальных правил принятия решений. Новые правила должны подключаться через
domain layer и не должны менять модуль загрузки и нормализации данных.

## Правила добавления нового функционала

1. Новый показатель добавляется в `configs/metric_registry.yaml` и расчетный код, если он требует новой формулы.
2. Новая таблица или новый источник данных добавляется через storage/table services, а не напрямую в маршруты API.
3. Новый endpoint должен вызывать application use case, а не напрямую собирать ranking/report pipeline из низкоуровневых сервисов.
4. Новая аналитика должна читать данные через DuckDB и возвращать только нужный объем строк.
5. Новое действие интерфейса должно быть встроено в линейный сценарий и иметь понятное состояние доступности.
6. Новые правила принятия решений должны использовать `DecisionCase`, `RuleProfile`, `Evidence` и `DecisionPassport`.
