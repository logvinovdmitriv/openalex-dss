# OpenAlex DSS

Русскоязычная СППР-лаборатория для воспроизводимого расчета и сравнения наукометрических показателей на локально материализованном срезе OpenAlex.

Ключевой принцип проекта:

```text
срез -> оценка объема -> загрузка -> локальные таблицы -> индексы -> аналитика -> отчет -> паспорта воспроизводимости
```

OpenAlex API не используется как рабочая аналитическая база. API нужен для поиска сущностей, оценки объема и загрузки корпуса. После материализации все фильтры, сортировки, рейтинги, графики и выводы строятся на backend по локальному срезу.

## 1. Что уже зафиксировано в репозитории

В репозитории есть две части:

1. Код программного комплекса.

## 3. Установка окружения

Требования:

- Python 3.12 или новее.
- Node.js 20 или новее.
- Доступ к интернету для загрузки зависимостей и OpenAlex API.

Создать виртуальное окружение:

```bash
python3.12 -m venv .venv
```

Если `python3.12` недоступен, проверьте установленную версию:

```bash
python3 --version
python3 -m venv .venv
```

Активировать окружение:

```bash
source .venv/bin/activate
```

Установить backend-зависимости:

```bash
.venv/bin/pip install -r apps/api/requirements.txt
```

Установить OpenAlex CLI, если планируется загрузка через официальный загрузчик:

```bash
.venv/bin/pip install openalex-official
```

Установить frontend-зависимости:

```bash
npm install
```

Виртуальное окружение `.venv`, `node_modules` и runtime-каталоги не коммитятся.

## 4. Настройка данных и API-ключа

По умолчанию рабочие данные создаются рядом с проектом:

```text
../openalex-dss-data
```

Можно задать свой путь:

```bash
export OPENALEX_DSS_DATA_DIR="/absolute/path/to/openalex-dss-data"
```

API-ключ OpenAlex задается только через переменную окружения:

```bash
export OPENALEX_API_KEY="..."
```

Не записывайте API-ключ в код, README, notebook, JSON, shell history или committed-файлы.

## 5. Запуск приложения

Из корня проекта:

```bash
./start
```

После запуска:

| Сервис | Адрес |
| --- | --- |
| Web UI | `http://127.0.0.1:5173` |
| API | `http://127.0.0.1:8000/api/v1` |
| Swagger | `http://127.0.0.1:8000/docs` |

Управление сервисами:

```bash
./status
./stop
./restart
```

Аналогичные команды доступны через npm:

```bash
npm start
npm run status
npm stop
npm restart
```

Логи находятся в `.runtime/logs/`.

## 6. Основной пользовательский сценарий

1. Открыть вкладку `Срез`.
2. Выбрать предметный срез OpenAlex.
3. Выполнить оценку объема.
4. Проверить фильтры, риски и план загрузки.
5. Загрузить или выбрать уже скачанный dump.
6. Дождаться нормализации и расчета индексов.
7. Открыть вкладку `Данные` для проверки локальных таблиц.
8. Открыть вкладку `Индексы` для просмотра базовых показателей и рейтингов.
9. Открыть вкладку `Аналитика` для распределений, корреляций и выводов.
10. Открыть вкладку `Отчеты` для report bundle, паспортов и контрольных сумм.

Важное правило: frontend не строит научные выводы по видимой странице. Таблицы, фильтры, сортировки, рейтинги и графики рассчитываются на backend по полному выбранному срезу или по явно указанному backend-запросу.

## 7. Базовые и дополнительные показатели

Базовый контур:

```text
P, C, C_frac, h, i10, g
```

Дополнительный контур:

```text
IUPV-S, PCI, IUPV-SB, ISLV, LRDI, n_cited5, frac_cited5
```

В выпускной работе базовый контур и дополнительный контур нужно описывать отдельно. `IUPV-S` является дополнительной метрикой робастного долевого цитируемого вклада и не заменяет общепринятые показатели.

## 8. Проверка проекта

Полный тестовый контур:

```bash
.venv/bin/pytest -q
npm run build:web
npm run test:e2e:web
.venv/bin/python scripts/validate_scientometric_dss.py --reset
```

Минимальный gate перед коммитом:

```bash
git diff --check
.venv/bin/pytest tests/test_repository_hygiene.py -q
npm run build:web
```

Детерминированный validation script использует локальный synthetic fixture. Он проверяет pipeline и структуру артефактов, но не заменяет реальный научный срез. Реальная апробация уже зафиксирована в `docs/научная_апробация`.

## 9. Чистка локальных артефактов

Обычная чистка:

```bash
npm run clean
```

Полная чистка локальной рабочей папки:

```bash
npm run clean:all
```

Полная чистка удаляет локальные зависимости и repo-local данные, но не трогает внешний каталог `OPENALEX_DSS_DATA_DIR`.

## 10. Что не должно попадать в Git

Не коммитятся:

- `.venv/`
- `node_modules/`
- `.runtime/`
- `.pytest_cache/`
- raw OpenAlex JSONL;
- Parquet/CSV runtime-таблицы;
- DuckDB/SQLite runtime-базы;
- API-ключи и `.env`;
- временные отчеты и тестовые выгрузки.

Исключение: в `docs/научная_апробация` намеренно хранится небольшой финальный доказательный пакет апробации, включая Excel-книгу и рисунки для выпускной работы.

## 11. Терминология для работы

Используйте формулировки:

- «базовые показатели»;
- «дополнительная метрика»;
- «описательная статистика»;
- «ранговая корреляция Спирмена»;
- «ящик с усами»;
- «сдвиг ранга»;
- «пересечение верхних N позиций»;
- «проверка допуска к анализу»;
- «полный отфильтрованный серверный срез».

Не используйте формулировки вида «метрика лучше всех» или «универсальная оценка автора». Корректная формулировка для `IUPV-S`: дополнительная метрика робастного долевого цитируемого вклада, проверяемая через сравнение с базовыми показателями.
